# Serial Broker V2.0.0 使用指南

这是V2.0.0正式版使用说明。main跟随最新版，旧版本源码归档为V1.0.0；请将新版解压到新目录，保留已有安装。

## 1. 安装与启动

解压 `SerialBroker-V2.0.0-win-x64.zip` 到新的目录，保留完整内容。需要Windows10/11 x64和.NET8 Desktop Runtime（Windows x64）；不是仅安装ASP.NET或普通.NET控制台运行时。

- `SerialBroker.exe`：多串口桌面工作区。
- `SerialBroker.Native.dll`：原C++串口核心的实例化桥接。
- `serialctl.exe`：兼容原版的命令行客户端。
- 其它DLL/JSON：GUI运行依赖，不能只复制EXE。
- `docs/V2-USER-GUIDE.html`：可由程序“帮助”按钮离线打开的本说明。

程序通常不需要管理员权限；当前用户需能访问对应设备和日志路径。启动后显示欢迎页，不会自动连接历史设备，也不会重放旧命令。

## 2. 新建多个串口连接

顶部“＋新建连接”或欢迎页按钮创建标签。每个标签对应一个物理COM，设置、状态、客户端、写入策略、监视和日志彼此独立。

1. 设备备注可自由命名、重名，支持表情；备注只是注释，COM号才是设备身份。
2. 物理串口框可下拉选择当前/历史端口，也可输入如COM4。下拉候选和选中内容显示设备管理器的友好名称，例如 `USB-SERIAL CH340 (COM4)` 或 `Silicon Labs CP210x USB to UART Bridge (COM7)`，不必另开设备管理器辨认。长名称在下方完整换行显示，悬停也能查看原文。“刷新”重新枚举本机设备；历史端口暂时不在线时保留已保存的名称并标明未连接。
3. 按设备要求填写波特率，格式固定8N1、无流控。
4. Telnet可独立启用；给每个同时运行的设备分配不同端口。
5. 设置日志根目录，按需选择DTR/RTS，点击“连接设备”。
6. 切换标签查看不同设备；关闭标签只断开这个设备。其它标签继续运行。

同一个COM不能重复代理。连接前关闭直接打开该COM的其它串口软件；旧版SerialBroker正在使用的端口也不能被新版同时占用。失败只影响当前标签，检查错误后手动重试。

连接中和连接/断开进行时不能编辑底层连接参数。先断开再改配置。打开串口或改变DTR/RTS可能使某些板卡复位，首次测试前确认板卡要求。

## 3. 历史记录和Telnet端口

有效配置在点击连接并通过参数校验时保存，即使之后设备不存在或端口绑定失败，也会记住该配置，便于修正后重试。仅仅创建草稿不会保存一条活动连接。

历史按规范化COM号（如com004统一为COM4）去重，最近使用在前，最多200项。保存：COM、Windows设备友好名称、波特率、用户备注、Telnet端口/开关、DTR/RTS和日志根目录。不会保存活动连接、RX/TX内容或CLI输入。设备友好名称只供识别，实际打开设备和生成管道时始终使用COM号；驱动未提供名称时退回COM号，旧历史不含名称也可继续使用。在场设备的最新名称优先，不会用旧缓存冒充当前适配器。

选择历史后回填之前的参数。历史Telnet端口只是默认值，可能已经被其它进程占用，用户可改。新设备端口从7000起，避开历史、当前工作区其它草稿和系统监听端口。用户手动输入端口后，不因继续输入新COM而自动覆盖。建议不会提前预留端口，连接前仍可能被其它进程抢占。

默认偏好位置：`%LOCALAPPDATA%\SerialBroker\workspace\preferences.json`。窗口尺寸/位置记录在同目录 `window.json`。可为独立工作区指定目录：

```powershell
.\SerialBroker.exe --data-directory "D:\SerialWorkspace\preferences"
```

使用同一个偏好目录的多个程序实例可能互相覆盖偏好，建议使用独立目录；物理COM及Telnet端口仍须分别规划。

## 4. 终端连接（以MobaXterm为例）

SerialBroker独占物理串口，终端改为连接该设备的本机Telnet端点：

1. 新建 **Telnet** 会话。
2. 地址填写 `127.0.0.1`，端口填写对应标签的Telnet端口，例如COM4使用7000、COM7使用7001。
3. 按设备选择字符编码；交互shell建议字符模式，关闭本地行编辑。
4. 不要再用Serial直接打开COM，也不要把入口当成SSH、Raw TCP或RFC2217。

每个Telnet会话接收对应设备的RX。代理不会把TX伪装成设备回显；设备没有回显时，可在RX/TX监视里核对发送字节。

基础Telnet入口只接受本机连接，未提供认证。本机其它进程可能连接；不需要时可在连接前取消启用Telnet。程序不配置系统防火墙，不支持把代理直接当作远程串口服务。

## 5. Agent和CLI

命名管道仍按物理串口区分：`SerialBroker.COM4`、`SerialBroker.COM7`。默认参数保留旧版COM3，建议自动化始终显式传入目标管道。

```powershell
# 监听COM4；stdout保留原始RX字节
.\serialctl.exe watch --pipe SerialBroker.COM4

# 发送UTF-8文本并追加回车
.\serialctl.exe send --pipe SerialBroker.COM4 --text "help" --cr

# 向另一设备发送Ctrl+C原始字节
.\serialctl.exe send --pipe SerialBroker.COM7 --hex "03"

# 在真实控制台中交互，Enter发送一行和CR，Ctrl+C退出
.\serialctl.exe interactive --pipe SerialBroker.COM7

# 查看版本
.\serialctl.exe --version
```

`--cr`追加0D，`--lf`追加0A，同时指定为CRLF。`--hex`接受成对十六进制数字和空白。每次发送（包括追加换行）最多4096字节；`--timeout 10000`设置权限/确认等待为10000毫秒。

GUI切换标签不影响CLI的目标，目标只由管道参数决定。stdout是设备RX，stderr是状态/错误，不要把两者合并后当作原始二进制数据保存。

新客户端会先收到最多64KiB的近期RX，再收到实时输出；因此连接后看到的内容未必是刚发命令的结果。`written`确认只表示Windows串口写操作完成，不代表设备已经执行完命令。超时、断开或确认丢失时字节可能部分/全部已发出，先查看设备输出，不要自动重发。

帧格式、权限申请和退出码详见同目录 `PROTOCOL.md`。V2没有改变SB协议，也没有提供一个含糊地指向“当前标签”的全局发送管道。

## 6. 写入策略和客户端

每次连接默认为共享写入。通过当前标签的策略下拉框切换：

| 策略 | 行为 |
|---|---|
| 共享写入 | 所有在线客户端可以发送，数据块由该设备唯一TX线程依次写入。不同客户端的整条shell命令仍可能交错。 |
| 单写入者 | 第一个发送有效数据或申请租约的客户端取得写入权；释放、断开或策略切换后可由其它客户端取得。 |
| 全部只读 | 拒绝发送及租约申请，仍可接收设备输出。 |

切换策略会清除旧租约并使旧策略下尚未开始的排队请求失效；已经交给Windows驱动的字节无法撤回。重复选中同一策略不会主动撤销租约。

选中客户端后点“断开选中客户端”，只关闭对应Telnet或管道客户端，不停止物理设备代理，也不影响其它串口。

## 7. 监视、主题和日志

监视区包含时间、事件/RX/TX方向及内容。默认按字节转义控制和非ASCII字符，例如CR为 `\r`；HEX查看每个原始字节。它是数据监视器，不是ANSI终端模拟器，完整终端呈现交给连接的终端软件。

- 暂停显示：暂停记录新的RX/TX显示项，仍显示状态事件；转发和磁盘日志继续，恢复后不补放暂停期间的监视项。
- 清空：清空当前标签的显示历史，不清除设备字节计数、磁盘文件或其它标签。
- 外观：明亮、暗色、暖色、淡蓝四种全局主题，立即同步到所有标签及监视区，并记住选择。
- 日志“打开”：打开文本框指定的根目录；目录不存在会尝试创建，路径错误显示在状态区。

监视队列最大约512KiB/2048项，显示历史最多2000项及约1MiB字节成本；达到限制仅略过/裁剪显示，避免阻塞设备转发。日志独立保存设备原始数据。

每次连接创建含时间、COM和进程ID的会话目录：

| 文件 | 内容 |
|---|---|
| rx.bin | 设备原始接收字节 |
| tx.bin | 完整成功写入的块；部分失败块不计入此文件 |
| events.log | 时间、连接/策略、方向、字节数和二进制偏移 |

RX/TX各上限128MiB，事件日志上限8MiB。达到限制或发生写盘错误后停止该会话全部日志并提示LOGGING DISABLED，串口转发继续。旧目录由用户管理，不自动轮转/删除。

## 8. 关闭、托盘与退出

点主窗口关闭或Alt+F4会隐藏到托盘，不断开任何设备。单击托盘图标恢复同一工作区；右键菜单可显示、打开帮助或退出。

需要真正停止程序时，使用主界面顶部或托盘菜单的“退出程序”。退出等待全部连接停止、I/O和回调结束，再关闭窗口和托盘。关闭单个标签只释放对应设备。

窗口尺寸、位置、最大化和主题会保存。重新启动恢复窗口偏好和历史，但不自动连接任何设备。关闭窗口前若还有手动操作，应先观察设备状态，代理不判断板端命令是否已经执行完。

## 9. 故障处理与人工验收

| 现象 | 检查 |
|---|---|
| GUI提示缺少运行时 | 安装.NET8 Desktop Runtime Windows x64，保留完整解压目录 |
| 无法打开COM | 设备是否在线；旧串口软件/旧代理是否占用；COM号是否变化 |
| Telnet绑定失败 | 端口是否被其他标签或进程占用；手动换端口再连接 |
| CLI连不上 | 目标标签是否已连接；是否显式指定正确COM管道；是否使用当前Windows用户 |
| 设备没有TX回显 | 核对监视TX和实际设备RX，不将写确认误当作板端执行结果 |
| 一个设备断开 | 检查该板连接后手动重连；其它标签无需断开 |
| 只看到托盘、窗口没了 | 单击托盘恢复；关闭窗口本来不会退出 |
| 历史/布局未保存 | 检查偏好目录写入权限和状态栏错误；独立实例使用不同数据目录 |

首次用于实际设备前，请重点用两个真实串口检查独立终端/CLI、单设备拔插、DTR/RTS、关闭驻留和显式退出。当前70项自动检查使用模拟设备、名称测试数据及正式库边界测试；另做本机设备元数据只读核对，不代表所有真实驱动、USB热插拔和长时间高吞吐均已覆盖。
